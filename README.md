# ai-engineering-training

These small C#/.NET 10 experiments help you learn by changing an input and inspecting the AI's response. Open [AIEngineeringTraining.slnx](AIEngineeringTraining.slnx) to load the projects.

- [Prompt engineering](01-prompt-engineering/prompt-engineering/README.md): change the instructions given to the AI and compare three summaries of the same resume.
- [Structured output](02-structured-output/structured-output/README.md): ask the AI to turn a resume into a JSON profile, then check its format and supporting facts.
- [Context engineering](03-context-engineering/context-engineering/README.md): choose which project descriptions the AI receives and compare its answer with one based on all six descriptions.
- [Function calling](04-function-calling/function-calling/README.md): let the model select a C# calculator, merge overlapping job dates, and answer with its verified experience total.

All four applications use Microsoft Agent Framework directly. Each lesson creates a ChatClientAgent, declares its prompts and generation settings in ChatOptions, and calls RunAsync. Function calling also creates native tools with AIFunctionFactory.Create. [AiClientFactory.cs](shared/shared/AiClientFactory.cs) manually registers internal provider strategies in its constructor and selects one to create a disposable IChatClient. [OpenRouterProvider.cs](shared/shared/Providers/OpenRouterProvider.cs) and [GeminiProvider.cs](shared/shared/Providers/GeminiProvider.cs) keep their connection details separate. [SettingsReader.cs](shared/shared/SettingsReader.cs) reads the selected provider into [ProviderSettings](shared/shared/ProviderSettings.cs). Each lesson uses native cancellation and checks its final response directly. The entry points print native exception messages. HTTP retries and compatible wire-format handling stay internal to the provider clients. Changing the configured provider or model leaves lesson code unchanged. The [shared tests](shared/shared.tests/shared.tests.csproj) exercise the native SDK and framework through a local HTTP transport.

Create `shared/shared/.env` from [shared/shared/.env.example](shared/shared/.env.example). Choose an AI provider with `AI_PROVIDER`, then configure its API key and model using the [shared setup instructions](shared/shared/README.md#run). Every application reads a copy of this same file from its build output folder. Rebuild after changing it. To try a lesson, open its project folder and run `dotnet run`.

The current provider strategies use the OpenAI .NET SDK to connect to either provider's Chat Completions endpoint. Lessons consume native AgentResponse and UsageDetails values. Requests send the lesson's fictional data to the selected remote service and may charge your account. Choose a model that supports the lesson's settings; the structured-output lesson also needs JSON Schema support, and function-calling needs function tools. See the [shared setup](shared/shared/README.md) and [Gemini compatibility documentation](https://ai.google.dev/gemini-api/docs/openai).

The shared HTTP retry policy allows two retries for temporary provider failures. Each model call normally sends one HTTP request and can make up to three attempts. Each complete agent run has one 120-second deadline covering every model turn, tool execution, and retry wait. Each lesson's README lists its model calls and maximum HTTP attempts. The full solution test run makes eleven model calls on success and can make up to 33 HTTP attempts; deterministic tests make no real API requests.

[AGENTS.md](AGENTS.md) explains how to add projects, share the setup code and settings, and write READMEs that teach each experiment in plain language.

To create another learning project, use the repository-local [create-learning-project skill](.agents/skills/create-learning-project/SKILL.md): write `$create-learning-project`, followed by what you want the project to demonstrate. The skill follows AGENTS.md for the code, checks, and README.
